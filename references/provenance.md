# Knowledge Provenance & Lineage Guidelines

## 1. Overview
A core differentiator of an OKF knowledge base is **verifiable lineage**. When an engineer or autonomous AI agent makes a decision based on this knowledge base, they must be able to trace every claim back to an authoritative origin:
* A production codebase or configuration file
* An external regulatory policy or technical standard
* A recorded customer interview or field observation
* A peer-reviewed RFC or design specification

---

## 2. Provenance Taxonomy in Frontmatter

Every knowledge document should cite its upstream sources using the `sources` YAML block:

```yaml
sources:
  - id: source:internal-repo
    resource: https://github.com/my-org/core-service
    title: "Core Service Repository & API Schema"
  - id: source:statutory-act
    resource: https://example.gov/statutes/act-2026.pdf
    title: "Digital Services & Data Protection Act of 2026"
```

## 3. Trust Invariants & Verification Workflow
1. **Initial Drafts (`status: draft`)**: Newly created concepts generated by AI agents or team members start with `verified: []`.
2. **Peer / Human Review (`status: stable`)**: Once verified by a domain expert, append the verifier's identity:
   ```yaml
   verified:
     - by: human:lead-architect
       at: 2026-09-26T12:00:00Z
   ```
3. **Automated Audits**: Automated CI jobs or linters that verify endpoint responsiveness or schema match can record machine verifications (`process:ci-verifier`).
